Pi-hole on Raspberry Pi 2 Model B v1.1

Network-wide ad blocker for Google Nest Mini + partial Spotify ad reduction

Hardware Notes

Board: Raspberry Pi 2 Model B v1.1 (900 MHz quad-core Cortex-A7, 1 GB RAM)

This board still runs Pi-hole well. DNS sinkholing is lightweight. Prefer Ethernet over Wi-Fi for stability. Use a decent 2 A+ power supply.

What You Need

  • Raspberry Pi 2 Model B v1.1
  • MicroSD card (16 GB+ Class 10 or better)
  • Power supply (2 A+ recommended)
  • Ethernet cable (strongly preferred)
  • Computer to flash the card

1. Flash the OS

  1. Download Raspberry Pi Imager.
  2. Choose Raspberry Pi OS Lite (32-bit) — best compatibility and lower overhead on the Pi 2.
  3. Click the gear / settings icon and configure:
    • Hostname: pihole (or whatever you like)
    • Enable SSH
    • Set username + strong password
    • Wi-Fi credentials only if you must use wireless
  4. Flash the card, insert it into the Pi, and power it on (preferably via Ethernet).

2. Install Pi-hole

SSH into the Pi:

ssh yourusername@pihole.local
# or use the IP address if .local does not resolve

Update the system and install Pi-hole:

sudo apt update && sudo apt full-upgrade -y
curl -sSL https://install.pi-hole.net | bash

During the installer:

  • Interface: eth0 (Ethernet) if possible
  • Upstream DNS: Cloudflare (1.1.1.1 / 1.0.0.1) or Quad9
  • Accept the default blocklists
  • Install the web admin interface
  • Log queries (yes for now so you can see what’s happening)
  • Privacy level: whatever you’re comfortable with

When it finishes it will show the admin URL and a temporary password. Set a permanent one:

pihole setpassword

3. Give the Pi a Static IP

Do one of the following:

  • Reserve the current IP in your router’s DHCP reservations (easiest), or
  • Edit /etc/dhcpcd.conf and set a static address outside the DHCP pool.

Reboot after this step.

4. Point Google Nest / Nest Mini at Pi-hole

  1. Open the Google Home app.
  2. Tap Wi-Fi → gear icon → Advanced networking → DNS.
  3. Choose Custom.
  4. Primary: the static IP of your Pi-hole
    Secondary: leave blank or put a public one as fallback (e.g. 1.1.1.1).
  5. Save.

Every device that gets a new DHCP lease (or is restarted) will now use Pi-hole. Restart the Nest Mini or toggle its network connection so it picks up the new DNS.

5. Extra Blocklists (including Spotify-focused)

In the Pi-hole web interface (http://your-pi-ip/admin):

Group Management → Adlists → add these (one per line):

  • https://raw.githubusercontent.com/x0uid/SpotifyAdBlock/master/SpotifyBlocklist.txt
  • https://raw.githubusercontent.com/Isaaker/Spotify-AdsList/main/Lists/pi-hole.txt
  • https://big.oisd.nl (OISD big list — only if the Pi handles it comfortably)

Then update gravity:

pihole -g

Realistic Expectations for Spotify

What Pi-hole / DNS blocking can do:

  • Blocks many third-party ad networks and tracking domains Spotify uses (DoubleClick, Google Analytics, various ad telemetry hosts, etc.).
  • Reduces or eliminates some banner / display ads and background analytics.
  • Cuts a noticeable amount of tracking and ad-related DNS noise across the free Spotify clients (desktop, mobile, web, and when casting to Nest).

What it usually cannot fully stop:

  • Audio ads that are delivered from the same CDN / domains as the actual music streams. Spotify has mixed more ad audio into its own infrastructure over the years, so pure DNS sinkholing cannot always separate “song” from “ad”.
  • In-app / in-stream ads that never do a separate DNS lookup for a classic ad domain.
  • Complete “Premium-like” ad-free experience on free accounts. Full silence of all audio ads is not reliable with DNS-only methods in 2026.

Practical results most people see:

  • Fewer random promos and less tracking traffic.
  • Some audio ads still appear, especially longer ones served from Spotify’s own edge.
  • Nest Mini / Google casting benefits more from the general ad/tracker blocking than from perfect Spotify silence.
  • If playback starts failing or songs won’t load after adding aggressive lists, open the Pi-hole query log, find the blocked domains that Spotify needs, and whitelist those specific ones while leaving the pure ad/telemetry ones blocked.

Recommended approach:

  • Start with the two Spotify-focused lists already added (x0uid + Isaaker).
  • Watch the query log while playing Spotify free for 10–15 minutes.
  • Whitelist only the domains that clearly break music playback.
  • Keep the pure ad / metrics / telemetry domains blocked.
  • Do not expect 100 % ad-free free Spotify from DNS alone — the lists still give useful coverage and privacy gain.

Spotify Coverage Details

Lists included in this guide:

  • x0uid/SpotifyAdBlock — classic hosts-style list of known Spotify ad and analytics domains, maintained for Pi-hole compatibility.
  • Isaaker/Spotify-AdsList (pi-hole.txt) — additional domains used for audio ads, banners and tracking.
  • Optional OISD big list — broader coverage of ads and trackers across the whole network (heavier; test on the Pi 2).

Typical domains these lists target:

  • audio-ads.spotify.com, ads-fa.spotify.com, adeventtracker.spotify.com
  • metrics.spotify.com, log.spotify.com, analytics-related hosts
  • Various DoubleClick / Google ad serving domains that Spotify has used
  • Other third-party ad and tracking endpoints that show up in free-client traffic

What to whitelist if things break:

  • Core Spotify / CDN domains required for actual audio delivery and Connect (spclient, scdn, spotifycdn, certain akamai / fastly hosts, etc.).
  • Only whitelist what the query log shows is necessary for playback. Leave pure ad and metrics domains blocked.

Spotify’s terms discourage circumvention of ads. This setup is presented as a local DNS privacy / blocklist configuration for your own network. Results vary by client, region, and how Spotify serves ads at any given time.

Extra Tips for the Pi 2

  • If the admin interface or gravity updates feel sluggish, disable query logging or reduce the number of heavy lists.
  • Most people never notice a difference on normal home traffic.
  • Keep the system updated occasionally with sudo apt update && sudo apt full-upgrade -y.

Quick Checks

  • Visit http://your-pi-ip/admin and watch the query log while using the Nest Mini and Spotify.
  • Force a DNS refresh on devices (restart them or toggle airplane mode).
  • Test a known ad domain — it should resolve to the Pi-hole’s IP or 0.0.0.0.
